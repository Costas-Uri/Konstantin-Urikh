# Общие положения

## Назначение 

Раздел описывает процесс создания и редактирования многосекционных окон Windows.

# Термины и определения

| **Термин** | **Определение** |
| :-: | :-: |
| Window | Окно, разделенное на секции Sections, которые содержат сущности системы (Views, Forms и пр.). |
| Section | Внутренняя секция (контейнер), добавленная в Window, и содержащая какую-либо сущность системы. |
| Tab | Вкладка в секции Section, в которую добавляются сущности системы. |

# Требования и ограничения

## Общие требования к решению

Функционал должен обеспечивать возможность:

- добавления нового Window,

- копирования Window,

- редактирования Window,

- удаления Window.

## Предусловия

Администратор / Пользователь авторизован в системе.

## 5. Пример применения Window с несколькими секциями

**Секция 1**

Секция 1"Links" (Стыковки) отображает список всех рейсов и является родительской по отношению к секциям 2 "Tours" (Задачи) и 3 "Arrivals" (Прилетные рейсы). 

1. Для передачи информации об изменениях в секции "Links" задаются две переменные, в которые будет записываться идентификатор записи, выбранной по нажатию ЛКМ в Links: 

   1. LinksToTours = position\_ref.\_id - связь объектов Links и Tours осуществляется через объект Positions,

   2. LinksToArrivals = \_id - идентификатор рейса, передаваемый в Arrivals.

2. Запись в переменные будет производиться одновременно по действию Action = post\_value при наступлении события Event = on\_row\_selection.

**Секция 2**

1. Секция 2 "Tours" является родительской по отношению к секции 4 "Drivers" (Водители). Для передачи информации об изменениях в секции "Tours" задается переменная: 

   1. ToursToDrivers = \_id.

2. В секции "Tours" для отображения требуемых записей после изменений в секции "Links"  необходимо прописать условие отбора по совпадению идентификатора в Tours с переменной из Links через объект Positions: 

   1. default\_location\_ref == window.LinksToTours.  
Здесь и далее приставка "window." указывает, что берется локальная переменная данного окна.

3. Для отображения записей секции "Tours" после изменений в секции "Arrivals" необходимо прописать условие отбора по совпадению идентификатора в Tours с переменной из Arrivals через объект Positions: 

   1. default\_location\_ref == window. ArrivalsToTours

**Секция 3**

1. Секция 3 "Arrivals" является родительской по отношению к секции 2 "Tours".   
Связь объектов Arrivals и Tours также осуществляется через объект Positions.   
Для передачи в секцию "Tours" информации об изменениях в секции "Arrivals" задается переменная: 

   1. ArrivalsToTours = position\_ref.\_id.

2. В секции "Arrivals" для отображения необходимых записей нужно отобрать в Arrivals только прилетные рейсы, плюс необходимо прописать условие отбора по совпадению идентификатора в Arrivals с переменной из Links: 

   1. bound == 1 and \_id == window.LinksToArrivals.

**Секция 4** 

1. Секция 4 "Drivers" не является родительской для других секций, переменные в ней не задаются.

2. В секции 4 "Drivers" условие для отображения записей при изменениях в "Tours":  

   1. \_id == window.ToursToDrivers 


**Логика работы:**

Если выделен рейс в секции 1 "Links", то секция 2 "Tours" покажет задачи для этого рейса.

Если пользователь выделит конкретный прилетной рейс, то в списке задач отобразятся только задачи этого прилетного рейса.

Если Пользователь выделит конкретную задачу, то в списке водителей он увидит доступных для этой задачи водителей.

Кроме того, отдельные секции могут представлять из себя набор разных Табов (Секция 2), каждый из Табов так же является списочным представлением View.

Необязательно должны быть связи между секциями или Табами - вкладка "All tours" отображает список задач, который никак не зависит от выбора какого-либо объекта в какой-то из других секций этого окна.
